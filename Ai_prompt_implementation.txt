# Stock Screener Frontend

## Project

Production React frontend for a stock screener and portfolio application.

## Stack

- React
- TypeScript
- Vite
- MUI
- TanStack Query
- React Router
- Financial DataGrid
- Charting library

Use feature-oriented architecture.

Business functionality belongs inside feature modules.

Shared components must remain business-agnostic.

API communication must not be implemented directly inside React page components.

TanStack Query manages server state.

Do not introduce Redux or another global state solution unless explicitly requested.

Use strict TypeScript.

Avoid `any`.

Do not disable TypeScript errors without a strong reason.

Prefer explicit domain types.

Do not duplicate types unnecessarily.

Never hardcode API URLs.

Use environment variables.

Do not call fetch/axios directly from page components.

Use the centralized API client.

Do not invent API fields.

Use the actual backend API contract.

## TanStack Query

Use TanStack Query for server state.

Do not duplicate server state into global state.

Use appropriate query keys.

Invalidate/update queries correctly after mutations.

Avoid unnecessary requests.

## UI

Use MUI components.

Use the centralized theme.

Do not hardcode colors.

Financial colors must come from theme tokens.

Positive values use the positive financial color.

Negative values use the negative financial color.

Neutral values use the neutral financial color.

Dark-first financial dashboard.

- dark navy
- charcoal
- subtle borders

- generous whitespace

Avoid:

- excessive gradients
- excessive rounded cards

- decorative UI that does not improve usability

Keep components focused.

Avoid premature abstraction.

Keep business logic out of presentational components.
